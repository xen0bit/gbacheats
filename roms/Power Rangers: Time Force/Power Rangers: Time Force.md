## 2. Executive summary

The game has a developer-intended **four-symbol password system** on the main menu
and in the pause menu. It is a checksum system, not a lookup table: every published
code is generated by the same algorithm. The input alphabet is 32 symbols
(`BCDFGHJKLMNPQRSTVWXYZ0123456789-`), so the raw space is 32^4 = 1,048,576 strings.
The validator is a linear GF(2) checksum (five parity equations) plus three small
semantic range gates. Exactly **10,416** passwords are accepted
(16 x 3 x 7 x 31), and the offline encoder/decoder in this report agrees with the
ROM on every tested accepted and rejected input.

All six published GBA codes were verified in the ROM and in mGBA. A previously
unpublished code, **`HLND`** (final level, Normal difficulty), was generated,
entered on the real password screen, and observed to start the final-level ending
sequence. Bounds were proven by four rejected inputs (one bad checksum, three
out-of-range fields).

A six-entry **hidden debug menu** (`continue`, `next chapter`, `next section`,
`quit`, `slowmotion`, `boost!`) is present in the ROM with a renderer and gate, but
it was not observed on any reachable screen; see §8.

## 3. How to reproduce

* Emulator: mGBA (SDL), `SDL_AUDIODRIVER=dummy`, Xvfb :318, `-3` scale.
* Keymap: A=`x`, B=`z`, L=`a`, R=`s`, Start=`Return`, Select=`BackSpace`,
  D-pad=arrow keys.
* Path: title → Start → **Password** (main-menu item 2). Keypad: 8 columns x 4 rows;
  Right/Left move one symbol, Up/Down one row (8 symbols). Press A on a symbol to
  enter it; after the **fourth** symbol the game validates automatically (no
  ACCEPT press needed). B deletes the last symbol.
* Verified codes (GameFAQs GBA list, all accepted):

  | Level | Password |
  |---|---|
  | 0 | HBLD |
  | 1 | KD4Q |
  | 2 | CNGF |
  | 3 | FLLF |
  | 4 | HDSF |
  | 5 | KGNF |

  `8QSD` (Cheat Happens "Final Level") is also accepted; it decodes to final level
  with difficulty field = 1.
* Novel code: `HLND` → **VALID PASSWORD ENTERED** → final-level/Ransik ending sequence.
* Rejected (all show **INVALID PASSWORD ENTERED**): `HLNX` (bad checksum),
  `KNNB` (level field 7), `TVND` (difficulty field 3), `KC67` (field A = 31).
* The in-game pause menu (Start) lists RESUME GAME, EXIT GAME, PASSWORD and also
  **displays the current password**, i.e. it doubles as a password generator.

## 5. Algorithm

Packing (0x0800E33C) is **little-endian in characters**: the first displayed
symbol is the least-significant 5 bits. For code `c0 c1 c2 c3` with alphabet
indices `d0..d3`:

```
packed = d0 | (d1<<5) | (d2<<10) | (d3<<15)      # 20 bits
```

Let `b[i]` be bit `i` of `packed` (b0 = LSB). Five parity equations
(0x08002778) must hold:

```
b[6]  = b[1] ^ b[8]  ^ b[11]
b[12] = b[2] ^ b[7]  ^ b[13] ^ b[15]
b[4]  = b[3] ^ b[9]
b[19] = b[5] ^ b[10] ^ b[14] ^ b[17] ^ b[18]
b[16] = XOR(b[0],b[1],b[2],b[3],b[5],b[7],b[8],b[9],b[10],b[11],
            b[13],b[14],b[15],b[17],b[18])
```

Three semantic gates must also pass:

```
A = b[5]+b[10]+b[14]+b[17]+b[18] <= 4      # all-ones forbidden
B = NOT (b[3] AND b[9])                    # both-set forbidden
C = b[1] | (b[8]<<1) | (b[11]<<2) <= 6      # value 7 forbidden
b[0] == 1                                   # implicit: validator returns packed&1
```

Encoder: choose the four field values, place their scattered bits, then compute
the five check bits from the equations above and emit four alphabet symbols.
The offline implementation was in `/tmp/prtimeforce/mint.py`.

## 6. Tables

| Field | Bits (LSB numbering) | Range | Meaning (confidence) |
|---|---|---|---|
| L | b2,b7,b13,b15 | 0..15 | stage/section selector (inferred from published codes: 5,5,8,12,13,15) |
| B | b3,b9 | 0..2 | difficulty (observed: 0 = Normal-published codes; 1 = 8QSD) |
| C | b1,b8,b11 | 0..6 | **level** (observed 0..5 for published Level 0..5; 6 = final) |
| A | b5,b10,b14,b17,b18 | 0..30 | auxiliary/state field (observed 30 on KD4Q, 0 elsewhere) |
| check | b4,b6,b12,b16,b19 | derived | parity bits |
| reserved | b0 | must be 1 | valid flag / return value |

Size: 16 x 3 x 7 x 31 = **10,416** accepted strings out of 1,048,576 (1 / 100.7).
Every accepted field tuple maps to exactly one string (verified by full enumeration).

Published-code decodes: HBLD (L5,B0,C0,A0), KD4Q (L5,B0,C1,A30),
CNGF (L8,B0,C2,A0), FLLF (L12,B0,C3,A0), HDSF (L13,B0,C4,A0),
KGNF (L15,B0,C5,A0), 8QSD (L7,B1,C6,A0).

Cheat Happens / SuperCheats codes `DBBR`, `GCB5`, `HCB9` fail the algorithm for this
GBA image; they are GBC-version codes mislabelled as GBA by those sites.

## 6b. Enumeration

* **Space defined:** 32-symbol alphabet, length 4, five parity bits, four scattered
  payload fields plus one fixed bit; 10,416 / 1,048,576 accepted (§5-6).
* **Offline model:** `enumerate.py` (full brute-force count + field extraction) and
  `mint.py` (field->code encoder). Both reproduce every published code.
* **Novel code:** `HLND` (L=5, B=0, C=6, A=0; packed 0x12905). It is on no published
  list. Entered on the real password screen: "VALID PASSWORD ENTERED", then the
  final-level Ransik ending sequence. RAM proof: 0x0200002C changed 0x00000000 →
  0x00012905 (savestate diff, §7).
* **Bounds proven by rejection:**
  - `HLNX` — flip check bit b19 of `HLND`: rejected.
  - `KNNB` — correct checksum, level field C = 7 (all three bits set): rejected.
  - `TVND` — correct checksum, difficulty field B = 3: rejected.
  - `KC67` — correct checksum, field A = 31: rejected.
  All four displayed "INVALID PASSWORD ENTERED"; the last three isolate the
  semantic range layer from the checksum layer.

## 7. Validation evidence

* **Observed (emulator):** title, main menu, Password keypad, Options menu
  (SOUND / DIFFICULTY / HELP), pause menu (RESUME GAME / EXIT GAME / PASSWORD /
  current password), acceptance of all six published codes plus HLND, rejection
  of the four bound-test codes, final-level ending after HLND.
* **Observed (RAM):** savestate `gbAs` diff (§16.13) shows packed code at EWRAM
  0x0200002C: 0 before, 0x00012905 after HLND. IWRAM flag bytes 0x0300001C and
  0x0300001E changed 0→1 on acceptance.
* **Derived (disassembly):** packer 0x0800E33C, validator 0x08002778, the three
  range helpers, the input handler 0x0800D82C, and the complete encoder are
  byte-for-byte consistent with the emulator results.
* **Inferred:** semantic names L (stage/section) and A (auxiliary state); the
  numeric field layout and bounds are derived, only the labels are inferred.

## 8. Unknowns

* The hidden debug menu's six entries are real (strings at 0x081A1DB0, pointer
  table at 0x081A1DF8, renderer 0x0800EF8C, gate 0x0800EED8) and its renderer
  handles input masks 0x84 / 0x02 / 0x0B. It was **not** displayed on the title,
  main, options, password, or pause screens, including an L+R+Start attempt.
  The gate returns 1 when at least two of four bytes at 0x0300235C/68/74/80 are
  zero (all four were zero in the captured states) or when the word at
  0x030023CC equals 5, so the gate condition alone is not sufficient; the screen
  that hosts this menu was not identified. This is a bounded negative for the
  screens walked, not a claim that the menu is unreachable.
* Field A's in-game effect was not isolated (only its rejection at 31 was proven);
  field L's exact label is inferred.
* No button-code cheats were found in the searched input/comparison code; the
  only developer-intended code surface positively identified is the password
  system and the dormant debug menu above.
