## 2. Executive summary

Crash Nitro Kart GBA is a Vicarious Visions kart racer with **no password, no keypad, and no
cheat-code entry screen**. Its developer-intended cheat surface is:

1. **A one-shot boot button gate that launches the hidden "Crash Party USA" minigame.**
   The published code is "hold L+R when turning on the game". The ROM check is at
   `0x08029852`: it samples `KEYINPUT` (`0x04000130`) once during early boot and tests
   `(0x300 & ~keys) != 0`. Because the mask is OR-ed against the two shoulder bits, **either
   shoulder button alone launches the minigame**; L+R is simply the published spelling.
   When the test passes the game LZ77-decompresses a complete 245,048-byte multiboot GBA
   image (`CRASH-PARTY`, header at `0x0845BB18`) to EWRAM `0x02000000`, clears all RAM except
   EWRAM (`RegisterRamReset(0xFE)`) and soft-resets into it. This was observed directly
   (registers, branch PCs, EWRAM image, execution at `0x0200558A`).
2. **A CHEATS list in OPTIONS with five values** (`NONE`, `ARTILLERY`, `TURBO`, `R/C KART`,
   `LUNAR`) created from the item table at `0x0803B0FC` with value descriptors `1..5`
   (`0x08032264`, +0xC each). On a clean save all four non-NONE values render as `LOCKED`
   (`0x080363AC`) and pressing A on them is inert. They are unlocked by adventure gem-cup
   wins or by a GameCube link bonus — save/achievement flags, not input codes.
3. **Unlockable characters/tracks** driven by the same save flags: 19 character names exist
   in the ROM; the arcade character screen shows 10 slots, the tenth `LOCKED`; the arcade
   track screen shows 12 tracks plus a thirteenth `LOCKED` slot (`VELO'S TRACK`).

The game also prints an **output-only web code** ("WEB CODE: %s", "ENTER CODE AT
WWW.VVISIONS.COM") on the high-score screen; it is generated by the game and typed into
the old vvisions.com site. There is no corresponding input field.

No debug menu exists: `strings` finds 0 hits for `password`, `passwd`, `debug`, `secret`;
the only `code` hits are the web-code banner and Shin'en audio-engine banners. The one
hidden screen is Crash Party USA, and it is fully enumerated below.

## 3. How to reproduce

Environment: mGBA 0.10.5 (`mgba` SDL), `Xvfb :267 -screen 0 1024x768x24`,
`DISPLAY=:267 openbox`, `SDL_AUDIODRIVER=dummy mgba -3 "Crash Nitro Kart.gba"`.

Default mGBA keymap used: A=`x`, B=`z`, L=`a`, R=`s`, Start=`Return`, Select=`BackSpace`,
D-pad arrows. A 150–180 ms hold is required (a short tap can be missed). All state below
was verified from RAM, not from images.

### 3.1 Crash Party gate (exact)

The gate is a **single early-boot sample**, at cycle ≈1,052,403 (before the title/animation
is interactive). A normal "hold keys after the window appears" test misses it. Reproduce
deterministically with mGBA's command-line debugger, which starts paused at cycle 0:

```
mgba -d -3 "Crash Nitro Kart.gba"
# in the debugger console:
b 0x08029852
# now hold L, R, or both in the mGBA window, then:
c
```

Run one of these variants:

| Variant | Keys held at `c` | `KEYINPUT` read | `r0` after `bics` | Branch |
|---|---|---|---|---|
| published | L+R | `0x00FF` | `0x0300` | taken to `0x0802985E` (launch) |
| **L only** | L | `0x01FF` | `0x0200` | taken to `0x0802985E` (launch) |
| **R only** | R | `0x02FF` | `0x0100` | taken to `0x0802985E` (launch) |
| bounds | none | `0x03FF` | `0x0000` | `beq` taken to `0x0802986E` (skip) |

On the launch paths, execution reaches `0x02000000` with `EWRAM[0x02000000] =
0xEA00002E` and `EWRAM[0x020000A0..0xAB] = "CRASH-PARTY "`. On the skip path, `EWRAM[0]`
stays `0x00000001` and the normal game continues.

For pure RAM proof without the debugger, mGBA savestates (`Shift+F1`, load with `F1`) were
decoded: the `gbAs` PNG chunk is zlib-compressed; EWRAM is at state offset `0x21000`,
IWRAM at `0x19000` (verified against the ROM copy of the IRQ stub at `0x03001400`).

From a clean save: `Return` (title → transition), `Return` (MAIN MENU). Then:

### 3.3 Savestate RAM layout (used for all menu evidence)

mGBA 0.10.5 `.ss1` = PNG; chunk `gbAs` → zlib → `0x61000` bytes:
`0x00000` state header (contains the ROM header + CPU), `0x19000` IWRAM (32 KiB),
`0x21000` EWRAM (256 KiB). `0x0200060C` is the live input object
(`+0` held, `+4` newly pressed, active-high).

## 5. Algorithm

### 5.1 Boot gate (reimplementation)

```c
// 0x08029818, called once from 0x0802A36C during boot
uint32_t page = get_byte_somewhere();       // observed 0xFF; r5
if (page == 31) goto launch;                // 0x0802984C
uint16_t keys = REG_KEYINPUT & 0x3FF;       // 0x08029852, active low
if ((0x300 & (uint16_t)~keys) == 0) return; // 0x08029854-5C: neither shoulder
launch:
    load_10(0x02000000, 0x0845BB18);        // 0x0802B6CC
    RegisterRamReset(0xFE);                 // keep EWRAM, clear the rest
    SoftReset();                            // reboots into the EWRAM image
```

Because the test is `0x300 & ~keys`, it is true when bit 9 (L) **or** bit 8 (R) is low.
Both orderings of extra buttons are irrelevant: bits 0–7 do not enter the test.

### 5.2 Embedded image decompression

`0x0802B6CC(dst, src)` reads the first word of `src`, takes its high nibble as a type, and
dispatches. For `0x10` it runs an LZ77-style decompressor whose flag convention is
**0 = literal, 1 = back-reference**, length = `(b1>>4)+3`, distance =
`((b1&0xF)<<8 | b2)+1`. Decoding `0x0845BB18` by that rule produces exactly 245,048 bytes
with a valid multiboot header (`0xEA00002E`, Nintendo logo, title `CRASH-PARTY 0000`) and
the strings `Crash Party USA`, `Round %d`, `You got all %d crystals!`, `Look for a reward
racing Velo!`. The first 232,904 bytes matched the live EWRAM image byte-for-byte; the tail
differs because the running minigame had already written its data/stack there.

### 5.3 Cheat list semantics

The CHEATS screen item table is `0x0803B0FC` = five `(name_text, value_desc)` pairs.
Each value descriptor is `{2, value, 0}` with value `1=NONE, 2=ARTILLERY, 3=TURBO,
4=R/C KART, 5=LUNAR`. In a clean save the four non-NONE items have their label pointer
replaced by `0x080363AC` (`LOCKED`) and their item flags at struct `+0x40` are `0`;
`NONE` has `0x02000101`. Pressing A on `NONE` returns to OPTIONS; pressing A on any
`LOCKED` row does nothing and stays on CHEATS (observed). The unlock is therefore a
save/achievement gate, not an input code.

## 6. Tables

### 6.1 Gate truth table (10-bit KEYINPUT space)

| L | R | other 8 bits | keys | launch |
|---|---|---|---|---|
| up | up | any | bit9=1, bit8=1 | no |
| **down** | up | any | `0x01FF` pattern | **yes (unpublished)** |
| up | **down** | any | `0x02FF` pattern | **yes (unpublished)** |
| down | down | any | `0x00FF` pattern | yes (published) |

## 6b. Enumeration

**Space definition (button gate).** One sample of a 10-bit active-low key state is taken
at `0x08029852`; bits 0–7 are ignored, bits 8 (R) and 9 (L) are OR-tested. Representable
states: 2^10 = 1024. Accepting set: 3/4 of the (L,R) combinations × 2^8 = **768 codes**.
The published list supplies exactly one of those combinations (L+R); **512 accepting
states are absent from every published list** (L-only and R-only, with any other buttons).

**Novel inputs entered and confirmed in the emulator.**
- **L only**: gate hit with `KEYINPUT=0x01FF`, `r0=0x0200`, Z=0, `PC=0x0802985E`; next
  breakpoint hit at `0x02000000`; `EWRAM[0]=0xEA00002E`, `EWRAM[0xA0]="CRASH-PARTY "`.
- **R only**: gate hit with `KEYINPUT=0x02FF`, `r0=0x0100`, Z=0, `PC=0x0802985E`; same
  EWRAM image and `CRASH-PARTY` header.
- L+R (published anchor) also confirmed: `KEYINPUT=0x00FF`, `r0=0x0300`, launch.

**Bounds proven by rejection.** No keys held: `KEYINPUT=0x03FF`, `r0=0`, Z=1, `beq`
taken to `0x0802986E`; execution returns to normal boot and `EWRAM[0]=0x00000001` (not
`0xEA00002E`), i.e. the minigame is not loaded. Pressing keys after boot (e.g. at the
title, ~3.5 s) does not trigger it because the gate is one-shot at cycle ≈1,052,403.

**Second gate path.** `cmp r5,#31` at `0x0802984C` jumps straight to the launch when the
boot page id equals 31, independent of buttons. In all observed runs `r5=0xFF`; the page
id's source (`0x0801F7A0`, a byte read from an object) was not enumerated. This is an
additional, input-independent path, not a code.

**Cheat-menu space.** Five values, of which four are save-gated. Locked rows were pressed:
the screen stays on CHEATS and no flag changes; the only selectable value (`NONE`) returns
to OPTIONS. There is no text/alphabet input anywhere in the cheats/options path.

**Negative search counts (whole ROM, `strings -t x -n 4`).** `password` 0, `passwd` 0,
`debug` 0, `secret` 0, `cheat` 5 (the `CHEATS` label + four `… CHEAT` reward messages),
`unlock` 4, `code` 4 (2 web-code strings + 2 Shin'en engine banners). Every menu screen
listed in §3.2 was entered and identified from RAM. No password/keypad validator exists
to enumerate.

## 7. Validation evidence

**Observed (emulator / memory):**
- `0x08029852` single-step with L, R, L+R and no keys; the `KEYINPUT` values, `bics`
  results and branch PCs in §6b.
- Launch path reaches `0x02000000`; EWRAM contains `0xEA00002E`, title `CRASH-PARTY `,
  ARM entry `0x020000C0` = `0xE3A00012`; PC sampled inside EWRAM at `0x0200558A`.
- 245,048-byte decompressed image with valid multiboot header and Crash Party strings.
- Every menu label pointer in §3.2 read from EWRAM; CHEATS rows show `LOCKED`.
- Locked-row A press is inert; NONE returns to OPTIONS.
- Clean 512-byte `.sav`; menu walk changes only byte `0x15`.

**Derived (instruction sequence):**
- OR semantics of the gate (`0x300 & ~keys`), accepting set 768/1024.
- Decompressor type dispatch and LZ77 flag convention (validated by decoding the block
  into a valid image).
- Cheat value IDs 1..5 from the descriptor table; screen record/item list addresses.

**Inferred (labelled):**
- `r5==31` is an attract-page index that selects the minigame unconditionally.
- Gem-cup/GCN-link unlock bits are save flags (published conditions + game strings + the
  observed locked state; the exact bit address was not isolated — see §8).

## 8. Unknowns

- The exact save byte/bit for each of the four cheat unlocks and the code that consumes
  them were not isolated. The menu shows the locked state and the ROM carries the four
  reward messages, but a clean save cannot reach the setter without playing the gem cups
  or using a GameCube link. No input code can substitute for it.
- The source and meaning of the `r5==31` page id.
- Crash Party USA's own save/reward format (three missiles for Velo) was not reversed.
- GCN link protocol and data layout.
