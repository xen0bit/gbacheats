**Embedded-header scan (Phase 0).** A full-ROM scan for the 156-byte Nintendo logo found **11 GBA headers**: file offsets `0x0`, `0xD6DD04`, `0xD71FC8`, `0xD90A6C`, `0xD94B9C`, `0xE1BA58`, `0xE1FE2C`, `0xE52F94`, `0xE57898`, `0xE8009C`, `0xE8490C`. Every one carries the same title `AGB KIRBY AM`, code `B8KE` and stock entry word. These are the game's multiboot/localised image copies in the upper ROM, not a 2-in-1 pack and not a trainer. No appended trainer, patch or cracktro was found. The only save artifact is a 32 KiB Nintendo SRAM/Flash image generated by mGBA during testing (removed at cleanup).

## 2. Executive summary

**There is no password system, no button sequence/code system, and no reachable debug menu in this retail ROM.** The in-game "cheats" are all **save-data unlockables** and one in-game input *trick*:

- Sub-games that unlock with completion (Crackity Hack, Kirby Wave Ride; plus Arena/Boss Rush at higher completion),
- Collection-Room features (Kirby Colors, Sound Test, Ability Room, CD Player, etc.),
- World features (Power Center, Secret Mirror, Meta Knight's Sword, Heart Container),
- One gameplay technique (keep the snorkel out of water with Sword/Master + `Up+B`).

Evidence for the negative (all primary where possible):

1. **Every reachable screen was walked** in mGBA with screenshots and saved RAM states (§7): boot logos, story intro, title, attract demo, FILE SELECT, GAME SELECT + START submenu, SUB-GAMES + per-game submenu, COLLECTION ROOM (40-slot grid + color selector), ERASE A FILE, and in-game + Tips. None has a code-entry field, a button-code prompt, or a debug menu.
2. **Text/bank checks**: all UI text is drawn from a font/tile bank (`strings` finds only the removed sound-test debug names at file `0x3852F0`, e.g. `boss_kyotu`, `select`, `pause`). A keyword scan across ASCII, case-folded ASCII, `+0x20`, `-0x20`, UTF-16LE and UTF-16BE returned **0 hits** for 30+ cheat keywords. 1,206 successfully decompressed GBA-LZ77 blocks contained **0** keyword hits.
3. **Published codes verified**: 3rd party cheat index list only unlockables/tricks — no password/button code. The widely published numeric strings (`02020FE6:03C9` debug room, `02020FE3:1B` unused state, CodeBreaker/ActionReaper lists) are **memory-edit codes**, explicitly out of scope. 3rd party cheat indexes state the debug menu was removed from the final game; its dev text survives only as a data table.
4. **Input-handler scan**: 9 Thumb PC-relative loads of `0x04000130` (KEYINPUT). The main-game ones at `0x0815250C`, `0x081526AE`, `0x081527D2` implement the standard `A+B+Select+Start` soft-reset check (`movs r0,#15; bics r5,r1; cmp r5,#15`) and normal key-state bookkeeping — **no key-mask sequence tables, no progress index, no action dispatch**. No button-code surface exists.

## 3. How to reproduce

**Emulator / display.** mGBA 0.10.5 (SDL), `SDL_AUDIODRIVER=dummy`, `Xvfb :315 -screen 0 1024x768x24`, `openbox`. Command: `mgba -3 "Kirby & the Amazing Mirror.gba"`.

**Keymap (verified on the title and menus):** A = `x`, B = `z`, L = `a`, R = `s`, Start = `Return`, Select = `BackSpace`, D-pad = arrow keys. Hold keys ~120–200 ms; short taps can be missed.

**Deterministic menu path (use savestate slot 1 saved at GAME SELECT):**

1. Boot → logos → story cutscene → title (`PRESS START`). The cutscene can be fast-forwarded by pressing A repeatedly; it also plays automatically at boot.
2. At title press **A** or **Start**; mash A to skip the intro → **FILE SELECT** (FILE 1/2/3, all 0% on a fresh save).
3. Press **A** on a file → **GAME SELECT**. Items: `START GAME` (submenu `ONE PLAYER` / `MULTIPLAYER`), `SUB-GAMES`, `COLLECTION ROOM`, `ERASE A FILE`. `B` closes the START submenu; Down/Up then moves the main cursor.
4. From `START GAME` press Down → `SUB-GAMES`: `SPEED EATERS` (available), `CRACKITY HACK` and `KIRBY WAVE RIDE` (both show a padlock on a fresh save). A enters; a `ONE PLAYER`/`MULTIPLAYER` submenu follows.
5. From `SUB-GAMES` press Down → `COLLECTION ROOM`: a 4×10 grid of 40 locked `?` collectibles; bottom panel shows `DEFAULT` / `CHANGE COLOR`; pressing A on the Kirby icon cycles the color.
6. From `COLLECTION ROOM` press Down → `ERASE A FILE` (FILE 1/2/3, `ERASE SELECTED SAVE DATA`).
7. In game: Start opens the `About Copy Abilities` tip (`B BUTTON QUIT`); B dismisses it. No pause menu with exit/cheat entries exists. L/R/Select on all menus had no visible effect.

**Codes tested:** no password or button code exists to test. Published *memory-edit* codes were checked against the ROM and rejected as out of scope (see §2/§6).

## 5. Algorithm

Not applicable. There is no password/checksum algorithm, generator, or button-sequence matcher to reimplement. The only input-driven behaviour is ordinary gameplay input and the standard GBA soft-reset combination checked at `0x0815250C`–`0x08152518`:

```
held = ~KEYINPUT & 0x3FF
if (held & 0xF) == 0xF:        // A+B+Select+Start simultaneously
    -> reset / soft-boot path
```

The documented snorkel trick (3rd party cheat indexes) is a gameplay input, not a code: with Sword/Master, at shallow water press `Up+B` (Master: `Down+B+Up` in order). It does not unlock content and was not treated as a code.

## 6b. Enumeration

Because there is no code system, §0.2's "mint a novel code" deliverable is replaced by the bounded-negative deliverable (§0.2 item 5, §16.3 "four different no"). The relevant spaces were enumerated completely:

**Cheat-surface space — enumerated and empty**

| Space checked | Method | Result |
|---|---|---|
| Password / code-entry screens | Visual walk of all 10 reachable screens (§3, §7) | **0** code-entry surfaces |
| ASCII keywords (`password`, `cheat`, `debug`, `secret`, `unlock`, `code`, `sound test`, `level select`, `warp`, `gallery`, … 30+ terms) | `strings -t x -n 4` + byte scan | 0 relevant hits (only dev SFX names) |
| Shifted / Unicode text (`+0x20`, `-0x20`, UTF-16LE/BE) | Full 16 MiB scan | **0** hits for all 30+ keywords |
| Compressed text (GBA LZ77 blocks) | Decompressed 1,206 valid blocks | **0** keyword hits |
| Button-code key-mask tables / progress index | 9 KEYINPUT xrefs disassembled | **0** sequence comparators; only soft-reset |
| Debug menu entries | 3rd party cheat indexes + screen walk | Removed from final build; **0** reachable entries |
| Publishable in-game codes | 3rd party cheat indexes | **0** passwords/button codes; only unlockables |

**Unlockable space — enumerated**

- 3 sub-games visible on a fresh save (1 available, 2 locked); 2 more sub-games (Arena, Boss Rush) documented as completion-gated.
- 40 collectible slots in the Collection Room (all locked on the fresh save), plus 1 Kirby-color selector with multiple colors (cycled with A in-session).
- 13 distinct unlockables/tricks documented in the two published lists and mapped in §6.1.
- 3 save files (FILE 1/2/3), each ~0x311 bytes in a 32 KiB flash image.

**Bounds proven by absence/rejection**

- `L`/`R`/`Select` on GAME SELECT and SUB-GAMES: no state change (screenshots `gs_L`, `gs_R`, `gs_Sel`, `sg_L`, `sg_R`).
- `A`/`B` on locked Collection-Room slots: no unlock occurs (screens `cr_A`, `cr_B`) — the 40 locked items cannot be opened by controller input.
- Published RAM-write codes were not entered as cheats (out of scope); the debug room is reachable only through a RAM write, so **no input can reach it**. This is a **dead/gated feature** (§16.3 categories 2 and 4), not an undiscovered code.
- No novel code could be generated or entered because no validator, alphabet, or key-mask table exists. This is a *bounded* negative, not an untested one.

## 7. Validation evidence

**Observed** (emulator screenshot + saved RAM state): all screens in §3/§6; file select 0%; GAME SELECT menu items; SUB-GAMES 3 entries with 2 padlocked; Collection Room 4×10 locked grid and working color change; ERASE A FILE; in-game Tips screen; savestate RAM layout.

Savestates retained during analysis (ROM folder, `.ss1`–`.ss9`): ss1 = GAME SELECT (baseline), ss4 = SUB-GAMES, ss5 = COLLECTION ROOM, ss6 = ERASE A FILE, ss7 = Speed Eaters entry, ss8/ss9 = repeated GAME SELECT samples for volatility measurement. These are generated artifacts and were removed at cleanup.

**Derived** (static): header/logo scan, keyword scans, LZ77 decompression counts, KEYINPUT xrefs and soft-reset disassembly, embedded-header identity, save-image layout.

**Inferred** (published, not exercised in emulator): the exact triggers for Arena/Boss Rush/Ability Room/Power Center/Meta Knight's Sword/CD Player/Heart Container/Secret Mirror/Sound Test and the snorkel trick. They are developer-intended unlockables per 3rd party cheat indexes but were not played through in this session; no claim is made that their effects were observed.

## 8. Unknowns

- Exact bit/byte offsets of individual unlock flags in the 32 KiB save image were not isolated (the fresh save leaves most of the image at `0xFF`; a completed save would be needed).
- The precise number of selectable Kirby colors and the full list of the 40 Collection-Room items could not be read without unlocking them; only the locked grid and color cycler were observed.
- The original debug menu's entry list is documented by 3rd party cheat indexes only indirectly (its dev text table survives); it is unreachable in the retail build, so its effects cannot be exercised.
- Whether the 11 embedded headers are strictly multiboot payloads or additional localised images was not determined; all carry identical identity and are not separately bootable from the title screen.
