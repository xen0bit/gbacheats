## 2. Executive summary

Star X has **two distinct in-game code systems**, both reached from
`Main menu → START → PASSWORD`:

1. **Three 6-character developer cheats** compared as literal ASCII strings:
   `GSHARD` (invincibility), `GSMAX` (full weapons), `GSBOOM` (infinite smart
   bombs). All three were verified in the emulator by reading their flag bytes.
2. **An 8-character level/ship code** with a genuine algorithmic validator: a
   40-bit word (8 × 5-bit symbols) of which 10 bits are GF(2) parity, plus 11
   decoded fields with individual range checks. 18 of the 20 published 8-char
   codes satisfy the model exactly; two published strings are corrupt.

A **novel password absent from every published list** was generated by the
recovered encoder and typed on the real screen: **`IGAFCDLG`**. It was accepted
(`BL 0x08008E28` returned `1`), set the level field `0x0300529C = 0`, and
started **AQUESS – PART 1** — the stage that published lists explicitly say
has *no password*. Rejection bounds were proven in-game with a broken-checksum
code and an out-of-range level code.

The accepted space is fully characterised: **94,348,800 distinct 5-bit codes**
(26 × 10!) out of 2³⁰ possible data words; the 64-glyph on-screen alphabet
reduces to 32 effective 5-bit values with documented aliases.

## 3. How to reproduce

* Emulator: mGBA 0.10.5 under Xvfb `:319`, `SDL_AUDIODRIVER=dummy`, 3× scale.
* Keymap (mGBA SDL default): A=`x`, B=`z`, Start=`Return`, D-pad=arrows.
  **Hold 40–50 ms for a single picker step**; 120 ms double-steps because of
  key repeat. Hold ENTER (`x`) 180 ms with ~1.1 s gaps when typing a code.
* Path: boot → language select (English) → `PRESS START` → main menu →
  `START` → `PASSWORD`.
* Entry: Left/Right selects a glyph, A commits one character, B deletes one
  (B on an empty field exits the screen), Start submits.
* To inspect RAM, launch `mgba -3 -d -t password.ss1 <rom>` and set Thumb
  breakpoints at `0x08012F94` (code gate), `0x08008E28` (level validator) and
  `0x08012FEE` (accept/invalid common tail). Input buffer is `0x0201DE20`;
  entered-character count is `0x03004AD4` (must be 8 for a level code).

## 5. Algorithm

### Character conversion (validator, `0x08008E2C`–`0x08008F34`)
For each of the 8 input bytes `c`:
```
d = (c - 'A') & 0xFF
v = d if d <= 25 else (c - 22) & 0xFF
```
so `A..Z → 0..25`, `0..9 → 26..35`. Only the low 5 bits of `v` are ever
tested, so digits `6..9` (32..35) are aliases of `A..D`.

### Parity (10 GF(2) equations, `0x08008F3C`–`0x0800909C`)
`v6` and `v7` are the check characters. With `b(x,i) = (x>>i)&1`:

```
b(v6,4)=b(v0,2)^b(v1,0)    b(v7,4)=b(v1,3)^b(v0,0)
b(v6,3)=b(v1,2)^b(v5,3)    b(v7,3)=b(v4,4)^b(v2,1)
b(v6,2)=b(v4,0)^b(v3,1)    b(v7,2)=b(v1,1)^b(v2,3)
b(v6,1)=b(v5,1)^b(v4,2)    b(v7,1)=b(v0,4)^b(v3,2)
b(v6,0)=b(v3,0)^b(v3,3)    b(v7,0)=b(v5,4)^b(v2,4)
```

Any mismatch jumps to `0x08009214` (return 0). `v0..v5` are therefore 30 free
data bits.

### Field extraction and range checks (`0x0800909C`–`0x0809212`)
```
A= b(v0,4)<<4 | b(v1,1)<<3 | b(v2,1)<<2 | b(v0,0)<<1 | b(v3,3)   # 0..27
   reject if (int16)(3*A-1) > 80 ; store (3*A-1)<<4 at 0x03004C30
B= b(v2,0)<<4 | b(v1,3)<<3 | b(v3,1)<<2 | b(v0,2)<<1 | b(v2,3)   # level-1, 0..25
C= b(v2,2)<<1 | b(v1,2)                       # <=2
D= b(v1,4)<<1 | b(v3,4)                       # <=2
E= b(v1,0)                                    # <=1
F= b(v4,1)<<2 | b(v4,4)<<1 | b(v5,2)          # <=4
G= b(v2,4)<<3 | b(v4,2)<<2 | b(v0,3)<<1 | b(v5,1)  # <=9
H= b(v4,3)<<2 | b(v5,4)<<1 | b(v5,0)          # <=5
I= b(v4,0)<<1 | b(v0,1)                       # <=2
J= b(v3,0)                                    # <=1
K= b(v5,3)<<1 | b(v3,2)                       # <=3
```
All checks passed → write fields, return 1. Finally the gate writes
`0x0300529C = B` (with the quirk `B==20 → 21` at `0x0801301E`).

### Encoder
Choose any 30 data bits (`v0..v5`), solve the ten parity equations for
`v6/v7`, then check the field bounds. Map `v≤25 → 'A'+v`, `v≥26 → '0'+v−26`.

## 6. Tables

### 6.1 On-screen alphabet (`0x087C7BD4`, 64 glyphs)

`[ ] ^ _`→5,7,8,9; `,`→`W`; `a`,`b`→11,12; `6`..`9`→0..3.

See §4 and §5. Field B is the stage index; A..K otherwise control unlabeled
ship/loadout state (see §8).

## 6b. Enumeration

* **Space definition.** 8 symbols × 5 effective bits = 40 bits. Ten GF(2)
  parity bits are determined by the first 30 bits. Field range checks leave
  **94,348,800 accepted distinct codes = 26 × 10!** out of 2³⁰ = 1,073,741,824
  possible data words (8.786917 %). Each level field `B=0..25` has exactly
  3,628,800 accepted codes; each A field 0..27 has 3,369,600. Counts were
  produced by a C brute-force over all 2³⁰ data words (`enum.c`) using the
  validator model that was itself verified against 18/18 good published codes
  and live breakpoints.
* **Glyph-level space.** The 64-glyph alphabet has many aliases into the 32
  effective values, so an accepted 5-bit word can have multiple on-screen
  spellings (e.g. digits `6..9` alias `A..D`); aliases are documented in §6.1.
* **Novel code (not in any published list): `IGAFCDLG`.** Derived from the
  published `IGIFCDLC` by clearing the level bit `v2.b3`, which changes field
  B from 1 to 0 while leaving all other fields identical. Typed on the real
  `PASSWORD` screen; at the validator entry the buffer read
  `49 47 41 46 43 44 4C 47` (`IGAFCDLG`), the call at `0x0801300E` returned
  `r0 = 1`, and `0x0300529C` read `0x00000000`. The game displayed the
  **AQUESS – PART 1** briefing — the level web lists say has *no password*.
  Screenshot: `novel_effectc.png` in the work dir (`/tmp/opencode/starx/`).
  A second encoder output, `IHIFCD1C`, is also accepted by the model.
* **Bounds proven by rejection (in game).**
  * `IGIFCDLA` (last char `C`→`A`, broken parity): reached the validator
    (`Hit breakpoint 1 at 0x08008E28`) then took the invalid branch
    (`0x08012FEE`, `r0=0`). → checksum layer enforced.
  * `MMDPUMWS` (parity valid, all other fields in range, level field B=30
    > 25): reached the validator, then invalid branch with
    `r2 = 0x0300529C` still loaded — the level range check rejected it.
    → field-range layer enforced independently of parity.
  * `2EA3QD01` and `YLMZAQVR` from the published list are rejected by the
    same parity equations; the two corrections above make them valid.
* **Screen enumeration.** Walked splash → BAM/Graphic State logo → language
  select (6 languages) → title `PRESS START` → main menu (`START`, `OPTIONS`,
  `PRACTICE`, `CREDITS`) → game type (`SINGLE PLAYER`, `PASSWORD`) → password
  screen → options (`DIFFICULTY`, `MUSIC`, `SOUND EFFECTS`, `AUTOCENTRE`,
  `INVERT Y`) → level briefing → gameplay intro. Screenshots:
  `walk_*.png`, `pw_savec.png`, `novel_effectc.png`. Text-bank entries
  `MUSIC TEST`, `SOUND TEST`, `TEAM SELECT`, `MAP 1-4`, `BRIEFING`, `SETUP`,
  `RESULTS` exist but no code/menu path to the first two was found (§8).

## 7. Validation evidence

**Observed** (emulator / debugger / RAM):
* All three cheat flags set to `0x01` at the addresses in §6.2.
* Input buffer bytes and length counter at `0x0201DE20` / `0x03004AD4`.
* `IGAFCDLG` reaches `0x08008E28`, returns 1, sets `0x0300529C=0`, starts
  AQUESS-PART 1 (screenshot).
* Both rejection codes reach the validator and then the invalid tail.
* 18/20 published codes reproduce exactly from the encoder.

**Derived** (disassembly / offline computation):
* All 10 parity equations, all 11 field formulas, the 64-glyph alphabet and
  its aliases, the 94,348,800 count, the two published-code corrections.

**Inferred:**
* Field A..K control ship/loadout/briefing parameters; their exact gameplay
  effects beyond stage selection were not exhaustively exercised.
* `MUSIC TEST` / `SOUND TEST` are likely leftover debug entries.

## 8. Unknowns

* Semantic names for fields A, C–K (only B = stage index was proven by RAM).
* Whether the two corrupt published codes are typos in web lists rather than
  a different ROM revision; the corrected spellings were derived, not
  submitted in-game.
* No button-code sequence or hidden debug menu was found; the text-bank
  entries `MUSIC TEST`/`SOUND TEST` have no reachable caller/table entry that
  was identified (bounded negative: all reachable menu screens walked, all
  three literal cheat strings and the entire level-code space characterised,
  no other input matcher present in the gate routine).
* Digit glyph navigation on the on-screen picker was imprecise due to X11 key
  repeat; letters `A`–`Z` were verified (single 40–50 ms presses).
