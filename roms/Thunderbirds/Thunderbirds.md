## 2. Executive summary

The game has exactly one in-game cheat surface: the **PASSWORD** screen on the title menu, which accepts a three-symbol password over a 16-symbol alphabet (`123456789BCDFHMT`). I located the input handler (`0x08002E8C`), the validator (`0x0800283C`), and a **closed 17-entry `u16` lookup table at `0x080DEE94`**. The validator packs the three entered symbol indices as `b0 | b1<<4 | b2<<8` (12 bits) and accepts a password iff that value equals one of the 17 table entries; otherwise it returns 0 and clears the entry buffer. The whole space is therefore 16³ = 4096 possible inputs with exactly **17 accepted** — a fully characterised, closed set.

Only **four** of those 17 codes are published (3rd party cheat index lists BCD / THM / H3D / 2DF for levels 2–5). The other 13 are unpublished. I entered several of them on the game's own screen in mGBA. Most importantly, **`734` is a hidden developer-credits code**: it plays the full Saffire staff group photo ("THUNDERBIRDS" caption), an effect absent from every published list I found. `T89` starts a Thunderbird 5 space mission (internal level 59). Rejection bounds were proven in-game with `BCC` (one symbol off a published code), `111` (table hole — the `0x0000` slot is deliberately outside the 17-entry scan), and a length-2 `BC` submission; all were rejected with the buffer cleared and no level change.

There is no second password system, no button sequence matcher, and no hidden debug menu reachable from the shipped UI within the searched spaces (§8). The game-over password display is generated by the same table (a generator routine at `0x080028A4` reads the table in reverse and writes the three symbols into `0x03001394..96`).

  * `BCD` — published; level variable `0x03000FC0 = 0x001E` (30), blue-lock scene.
  * `734` — **novel**; staff photo, `0x03000FC0` briefly `0xFFFF` then `0x0030` (48).
  * `T89` — **novel**; Thunderbird 5 space mission, internal level 59.

## 5. Algorithm

Entry mechanics (derived from `0x08002EA0`):

```
row = byte[0x0300138C]; col = byte[0x030013A0]
symbol = row * 8 + col              # 0..15
buffer[length] = symbol             # 0x03001394 + length
length += 1
if length <= 2: return              # UI waits for a third symbol
# after third symbol: reset row/col, screen state = 2, sound 0x2A
```

Validator `0x0800283C` (reimplemented in `enumerate.py`):

```
byte[0x030013C8] = 0                # clear valid flag
if buffer_length <= 2: return 0     # lives at 0x030013C0 in the real call
packed = buffer[0] | buffer[1]<<4 | buffer[2]<<8
packed &= 0xFFFF
match = 0xFFFF
for i in 0..16:                     # SEVENTEEN entries, inclusive
    if packed == u16_table[0x080DEE94 + 2*i]:
        match = i
if match == 0xFFFF: return 0
apply(match)                        # call 0x080025D8
return 1
```

Notes:
* There is **no checksum** — this is a pure closed literal table. The "checksum" is membership in the 17-entry table.
* The loop bound is `cmp r0,#16; ble`, i.e. indices 0–16. Word 17 (`0x0000` → `111`) is deliberately present as data but outside the accepted set — this is why `111` is rejected. Word 18 (`0x11D4`) has a nonzero high nibble and is also outside.
* The generator at `0x080028A4` uses the same table: given an internal index it reads `u16 table[i]` and writes `v & 15`, `(v>>4)&15`, `(v>>8)&15` into the three buffer bytes. There is no way to generate a string the validator rejects (other than the screen's own alphabet limits).

## 6b. Enumeration

**Space definition.** Three symbols × 4 bits each = a 12-bit packed value; 16³ = **4096** representable inputs. The validator performs no arithmetic — it is a 17-entry lookup. Therefore the accepted set is exactly **17 codes out of 4096** (0.415%). Full-space enumeration was run offline with `enumerate.py` (reimplementation of the ROM validator) over all 4096 triples: 17 accepted, all matching the ROM table; the 17 packed values are unique, all < 4096, and the high nibble of every table word is zero (no aliases from unused bits). The result is a **closed set**: §16.9's "run the validator over the whole space" is satisfied here by the arithmetic of a 17-entry loop plus a full reimplementation cross-checked against the live ROM on accepted and rejected inputs.

**Novel code minted and confirmed in-game.** `734` (packed `0x0326`, table index 16) appears in no published list I found (3rd party cheat index-adjacent coverage, and the "Hardware Crackmes: 100 GBA Games" novelty list were checked). Typed on the game's own PASSWORD screen:

* Screenshot `novel_734b.png`: buffer shows `734`, cursor on DONE.
* After submission, screenshot `novel_734_result.png`: full Saffire staff group photo with "THUNDERBIRDS" caption — the hidden developer credits screen.
* RAM evidence: `0x030013C0` (length) = 3; `0x03000FC0` briefly `0xFFFF` then `0x0030` (48); no other input touched.

A second novel code, `T89` (packed `0x087F`, index 5), was typed on the same screen: screenshot `novel_T89_result.png` shows a Thunderbird 5 space mission with the internal level set to 59. Both are absent from the published four-code list.

**Bounds proven by rejection (in-game).**

| Test | Expected from model | Observed in emulator |
|---|---|---|
| `111` (packed `0x0000` = table word 17, outside the 0..16 scan) | reject | buffer cleared to `---`, cursor jumped to BACK, no level change |
| `BCC` (published `BCD` with last symbol changed) | reject | after submit, buffer cleared to `---`, length `0x030013C0 = 0`, level unchanged (`0x001D`) |
| `BC` then DONE (length 2) | reject by `length <= 2` guard | buffer stayed `BC-`, no level change; subsequent A cleared length to 0, level unchanged |
| A 12-bit value in the table gap (e.g. `0x0000` above) | reject | covered by `111` |

Counts: 17 accepted / 4096 tried offline; 6 inputs tested live (3 accepted: `BCD`, `734`, `T89`; 3 rejected: `111`, `BCC`, `BC`). The UI's 16-symbol grid can express every one of the 17 accepted codes, so all 17 are reachable on a retail cart.

## 7. Validation evidence

* **Observed** (emulator/RAM): boot/title/password/pause/options/gameplay screens and screenshots; `BCD` → level `0x001E` blue-lock scene; `734` → staff photo; `T89` → Thunderbird 5 space mission; rejection clears; breakpoint hit at `0x08002604` with r0=0, r1=`0x08002618` for `BCD`; savestate diffs showing the buffer in IWRAM and no EWRAM changes.
* **Derived** (disassembly): symbol encoding `row*8+col`; packing `b0|b1<<4|b2<<8`; 17-entry loop bound; apply jump table and all level/sub-level writes; generator routine reading the same table; single call site of the validator (`0x08002EE8`).
* **Inferred**: field names "level"/"sub-level" (from destination addresses); the credits routine's `0xFFFF` sentinel handling; the game-over screen's password display (string bank + generator routine, not reached by natural play in this session).

## 8. Unknowns / bounded negatives

* **Game Over screen not walked.** The strings `GAME OVER` / `PASSWORD` / `PRESS START` exist at `0x0815FC1C`–`0x0815FCBC`, and the generator routine at `0x080028A4` writes the same 3-symbol format into `0x03001394..96`, so a game-over password display is **Derived/Inferred** but not **Observed**; repeated attempts to die in the starting room did not reduce lives. This is a coverage gap, not a claim that the screen is absent.
* **No second password system.** Literal searches (ASCII, `+0x20`, UTF-16) for the alphabet and for any other code-like string found no second alphabet/table; the validator has exactly one caller (`0x08002EE8`) and the table exactly one validator reference (`0x08002898`). A second system using an unrelated glyph encoding cannot be excluded by those searches alone.
* **No button-code table.** A scan for runs of ≥5 consecutive valid KEYINPUT masks found 36 candidates, all in high ROM regions (`0x0817899A`+) that are graphics/level data, not code tables; no published button codes for this SKU were found. No hidden debug-menu strings exist in the ASCII bank (searched `debug|cheat|menu|invalid|secret|level select|bonus`; only gameplay text and `ai invalid message` at `0x08161E64`).
* **Sleep-mode confirmation** (`ENTER SLEEP MODE?`, `0x0815FAD8`) exists but was not entered (Select+L+R on the game), so its post-screen state is untested.
* No ROM or copyrighted assets were redistributed; all screenshots are local verification artifacts in `/tmp/thunderbirds`.
