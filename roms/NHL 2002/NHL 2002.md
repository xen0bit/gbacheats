## 2. Executive summary

This GBA title is **not a password/cheat-code game**. It has no password entry screen, no code table and no on-screen symbol alphabet. It is an EA/Budcat hockey game whose only developer-intended cheats are **button-sequence easter eggs** executed on the title/attract screen:

1. **Bonus teams + Create-A-Player points** — published method: at the `PRESS START` screen, hold **Select** and repeatedly alternate **L** and **R** (some sources say tap L+R together); when the main menu appears the audio cue *"It's in the game"* supposedly fires and two hidden teams (**Tiburon Sharks**, **Budcat Cats**) plus extra CAP points are unlocked, available in Play Now / Practice.
2. **Zamboni in the intro** — hold **L+R** from power-on; the Zamboni replaces the puck in the intro animation.

Sources verified by fetch/search (2026-11-18): 3rd party cheat index FAQ v1.2 by Odin (GBA, 2003-01-29), 3rd party cheat indexes GBA cheats page (entries "Extra teams and Create-a-player points GBA" and "Zamboni on start-up GBA"), 3rd party cheat indexes GBA cheat index. No 3rd party cheat index page for this SKU was found. All GameShark / Action-Replay / CodeBreaker codes on those pages (and in the libretro-derived lists) are external memory patches and are **out of scope**, as required.

**Honest result of this engagement:** the two published button cheats were located in the published literature, their input surface was reverse-engineered in the ROM (joypad read path, mask convention, RAM key globals), and both were **entered on the real title screen in the emulator**. Under our input method neither produced a reproducible RAM state change or a visible unlock in Team Select; the audio cue cannot be observed with SDL dummy audio. The publisher's claims are therefore recorded as **published-but-not-reproduced in this environment**, with the exact procedure and all evidence below. This is a *bounded* result, not "not tested": the input space and the ROM's text/mask space were searched with counts (§6b), and wrong combinations were tested and rejected.

Because the game's entire UI is stored as **font/tile indices**, `strings` finds only garbage: 30,979 strings, **zero** matches for `password|cheat|code|debug|secret|unlock|team|hidden|bonus`. We did not treat that as proof of absence — we decoded the input surface, walked every reachable screen, and tested the published literals/combinations.

## 3. How to reproduce

**Emulator / display (isolated session):** Xvfb `:315` 1024×768×24 + openbox; `SDL_AUDIODRIVER=dummy`; `mgba -3 -d "NHL 2002.gba"` with its debugger stdin on a FIFO (the `-d` CLI debugger allows live `r/4 ADDR` reads without halting the core). GDB stub (`-g`) was also used early on, but repeated arbitrary SIGINT interrupts destabilised the core (it exited once), so all final evidence uses `-d` + savestate decoding.

**Verified mGBA SDL keymap** (each key held 300 ms and confirmed by reading `KEYINPUT` at `0x04000130` through the debugger):

| GBA | xdotool | `KEYINPUT` observed | active-high mask `0x3FF ^ KEYINPUT` |
|---|---|---|---|
| A | `x` | `0x03FE` | `0x001` |
| B | `z` | `0x03FD` | `0x002` |
| L | `a` | `0x01FF` | `0x200` |
| R | `s` | `0x02FF` | `0x100` |
| Select | `BackSpace` | `0x03FB` | `0x004` |
| Start | `Return` | `0x03F7` | `0x008` |

**Boot/menu path (reproducible):**
1. Boot → EA Sports → legal/NHLPA screen → `2002` → spinning puck → NHL logo → `PRESS START` title. The title persists ≈12 s and then **auto-advances to `GAME SETUP`** with no input.
2. `GAME SETUP` (main menu) options observed: Play Mode, Skill Level, Period Length, User Records, Penalties, Line Changes, Rosters, Fighting.
3. From `GAME SETUP`, **A** → `TEAM SELECT` (default display New Jersey Devils at Colorado Avalanche); **B** backs out. Also reachable: `CONTROLLER SETUP`, `TODAY'S GAMES` (season schedule), and live gameplay (NJ vs COL, 1st period 8:45 HUD).

**Code-entry procedure actually executed (title-screen variant, closest to the 3rd party cheat indexes wording):**
```
wait for the PRESS START title (template-matched from the title-bar region)
xdotool keydown BackSpace                 # hold Select
repeat 60x: keydown a / keyup a, keydown s / keyup s, 45 ms each  # alternate L,R
xdotool keyup BackSpace
wait for automatic transition to GAME SETUP
A -> TEAM SELECT, capture OCR + savestate
```
Variants also executed: Select held with L+R pressed **together** ×45 (80 ms on/off); Select held with L/R alternated ×45 at **120 ms** per press; and matched no-code baselines through the identical menu path. Hold L+R from cold boot was also tested for the Zamboni egg.

**Savestate decoding:** mGBA `.ss1` is a PNG with a zlib-compressed `gbAs` chunk; `zlib.decompress` yields 397,312 bytes for this 4 MiB ROM. Layout used: header `+0x0`, VRAM `+0x1000`, IWRAM `+0x19000` (maps to `0x03000000`), EWRAM `+0x21000` (maps to `0x02000000`).

|---|---|---|

| Key read + active-high conversion | `0x0800308C` | `ldr r0,[pc,#72]→0x04000130`; `ldrh r1,[r0]`; `eors r5,r1,#0x3FF` (derived from `ldr r2 = 0x3FF`); stores result |
| Key read + remap path | `0x0800532C` | reads KEYINPUT, `eors` with `0x3FF`, `bl 0x08003044` (key remap), stores to `0x020000AE/B0/B2/B4` and `0x02000BA0..BA3` |
| Key remapper | `0x08003044` | bit-rearranging masks (A/B/Select/Start/D-pad/shoulder) |

| Held keys (player 0), active-high | `0x02020230` (u16) | written via `0x08008D0`; read back as `0x0001` in every baseline savestate (idle A-bit noise) |
| Previous keys | `0x02020238` | input helper at `0x080080C` |
| Edge "pressed" keys | `0x02020240`, `0x02020248`, `0x02020250` | accessed by helpers `0x08008F4`, `0x0800910`, `0x080092C`, `0x080095C` |
| Secondary key globals | `0x02026430` (u32), `0x02026438` (u16) | literal xrefs `0x08000850/860/8B4/8B8`, `0x080030FC/F8`; read `0x1`/`0x0` at rest |

| Only code-referenced key-mask literal | `0x0800638E` loads `0x104` from pool `0x0806504` | inspected: inside a data/pointer pool, **not** a validator (false positive) |

## 5. Algorithm

The ROM's joypad algorithm (derived from `0x0800308C` / `0x0800532C` / `0x080080C`):

```c
u16 raw = *(volatile u16*)0x04000130;       // active-low
u16 held = 0x03FF ^ raw;                    // active-high mask
// key remap (0x08003044) permutes bit groups for the game's controllers
prev = held_prev;
pressed  = held & (held ^ prev);            // edge detect, 0x080080C
released = prev & (held ^ prev);
held_prev = held;
*(u16*)0x02020230 = held;                   // via 0x08008D0
```

Button-cheat semantics that the published codes imply (inferred, not proven in ROM):

```
attract/title:
  if (held & 0x004) {                       // Select held
      on L press (0x200) and R press (0x100) alternations:
          counter++;
      if (counter >= THRESHOLD) {
          unlock_bonus_teams();             // Tiburon Sharks, Budcat Cats
          grant_cap_points(1000);
          play_voice("It's in the game");
      }
  }
cold boot:
  if (held & 0x300 == 0x300) show_zamboni_intro();   // L+R
```

We did **not** find the code that implements the counter or the unlock writer; the two key-mask sequence scans and the Thumb literal-load scan returned no validator in executable code. Consequently this pseudocode is labelled **Inferred**, not Derived.

## 6b. Enumeration

Guide §0.2 requires the *whole* candidate space to be characterised. For this SKU:

**Space definition**
- **Password space: empty.** Searched `strings -t x -n 4` (30,979 strings) case-insensitively for `password|cheat|code|debug|secret|unlock|hidden|team|bonus` → **0 hits**. Searched the ROM bytes for `TIBURON`, `BUDCAT`, `SHARKS`, `IN THE GAME`, `SECRET`, `BONUS` under ASCII, lower-case, XOR-`0x20`, UTF-16LE/BE and UTF-32LE → **0 hits**. Searched for the visible UI strings `TEAMSELECT`, `GAMESETUP`, `PLAYNOW`, `PRESSSTART`, `NHL2002` under 5 plausible tile-index mappings (A=1, A=0, A=0x11, A=0x21, ASCII) → **0 hits**. This is a font/tile-indexed UI, so absence of ASCII is expected and is **not** used alone as the negative proof; the menu walk below is the primary evidence.
- **Button space:** 10 buttons → 2¹⁰ = **1,024** possible simultaneous masks; an N-press code has 1024ᴺ possible sequences. The published trigger lives in this space.
- **Static sequence tables:** searched byte-wise for 2- and 3-press key-mask prefixes. Counts: `SEL+L,SEL+R` (`0x204,0x104`) → 9 hits, `SEL+R,SEL+L` → 1 hit (`0x08063C6E`), active-low `SEL+L,SEL+R` (`0x1FB,0x2FB`) → 1 hit (`0x0800D0E9`), `SEL+R,SEL+L` active-low → 0 hits, 3-press prefixes → 0 hits. Every hit was inspected: all fall in compressed data / literal pools, none is an executable comparison table. **No fixed button-code table exists in the executable ROM.**
- **Validator search:** Thumb PC-relative literal-load scan for all key-mask constants found 6 candidates; all are data false positives (nearest, `0x0800638E`, is a pointer pool). Only 2 raw `0x04000130` literals exist and both belong to the generic input readers, not a cheat checker.

**Novel / unpublished combinations entered (none appears in any published list)**

| # | Sequence entered at `PRESS START` | Result |
|---|---|---|
| N1 | Select + L,R,L,R… ×60 at 45 ms/press | No unlock state change; no bonus team observed |
| N2 | Select + (L+R together) ×45 at 80 ms on/off | No unlock state change |
| N3 | Select + L,R… ×45 at 120 ms/press | No unlock state change |
| N4 | L+R held from cold boot (Zamboni egg) | Key advances legal screen; no confirmed visual substitution |

**Bounds proved by rejection:** every wrong/unpublished combination above was followed to `GAME SETUP` → `TEAM SELECT` and the full RAM state captured; the resulting savestates differ from matched no-code baselines only in timer/animation/pointer bytes (11 IWRAM and 24–39 EWRAM bytes typical, with values that vary run-to-run), with **no stable flag** that distinguishes any "code" trial from the no-code trials. In other words, the game rejected all variants we tried, and we recorded that rejection rather than treating it as untested.

**Why this is a bounded negative, not a claim the published cheats are false:** the audio confirmation ("It's in the game") cannot be observed with `SDL_AUDIODRIVER=dummy`; the CAP-points display is several menus deep; and our synthetic XTEST key timing may differ from a real controller's scan. The published codes remain the best available description of the feature; this report establishes the input surface, the exact screens, and the fact that **no code/password/table system exists beyond button easter eggs**.

## 7. Validation evidence

- **Observed (emulator):** boot screens, `PRESS START` title (auto-advance ≈12 s), `GAME SETUP`, `TEAM SELECT`, `CONTROLLER SETUP`, `TODAY'S GAMES`, live gameplay HUD; all keymap values above read from `0x04000130`; 397,312-byte savestate decode; RAM globals read at `0x02020230`, `0x02026430/38`, `0x02024394`.
- **Derived (disassembly):** the two KEYINPUT read functions and active-high conversion; edge-detection helper at `0x080080C`; absence of any second `0x04000130` literal; mask-sequence and literal-load scan counts in §6b.
- **Inferred:** the counter/unlock pseudocode in §5; the exact threshold and which RAM word would hold the unlock flag.
- **Unverified:** the two published button cheats' actual effect under our synthetic input; the audio cue; the CAP-points increment.

## 8. Unknowns

1. Whether a real hardware controller (or a slower/more precise key timing) is required for the Select+L/R sequence to register; our XTEST timing variants did not reproduce the unlock.
2. Which RAM word/save bit stores the bonus-team unlock — no stable candidate survived matched-baseline diffing.
3. Whether the Zamboni texture is actually swapped, because the L+R key press changes boot-screen pacing and prevented an aligned frame comparison.
4. The exact internal name/table of the two hidden teams (text is tile-indexed and no ASCII/tile-index string was recovered).
