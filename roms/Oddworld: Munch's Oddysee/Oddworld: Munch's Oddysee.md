## 2. Executive summary

The game has a genuine **8-character password system** on the main-menu `PASS WORD` screen and in the in-game pause menu. The on-screen alphabet is 50 symbols (`BCDFGHJKLMNPQRSTVWXZbcdfghjklmnpqrstvwxz1234567890`), stored verbatim at ROM `0x083E71FC`. There are two layers:

1. **Two hard-coded plaintext developer codes** compared byte-for-byte: `THQMPMD1` (unlocks the Music Player — the main-menu `Secret` label changes to `Music Player`) and `THQHP100` (sets infinite-health flag byte `0x030039FC = 1`). Both strings are in ROM at `0x083E722F` / `0x083E7238`.
2. **An algorithmic validator** at `0x0803DB90` that decodes the 8 alphabet indices into an 8-word payload, checks a 6-bit accumulator and a 4-bit ripple count, then packs the result into a level index at `0x03004964`. All twelve published "skip to level" codes are generated by this algorithm; **none is stored literally in the ROM**.

I reimplemented the decoder exactly (it accepts all 12 published codes and rejects garbage), used mGBA's CLI debugger as an oracle (`§16.19`) to call the ROM's own validator on synthesized inputs, minted **novel codes for unadvertised levels**, and typed one (`BwvzC35R` → level 10) on the real on-screen keyboard. RAM (`0x03004964 = 0x0A`) and the pause-menu level name `Journey` confirm the effect. An invalid code (`BBBBBBBB`) produces "Incorrect Password!", bounding the rejection path.

Notable finding: the published labels are wrong for half the list — the codes labelled "level 9…13" actually decode to levels **11…15**, so **levels 9 and 10 are unadvertised** and reachable with minted codes (§16.15).

## 3. How to reproduce

- Emulator: `SDL_AUDIODRIVER=dummy mgba -3 <rom>` under `Xvfb :318` / `openbox`.
- Keymap (mGBA SDL defaults, verified on screen and via `0x03000668` cursor reads): A = `x`, B = `z`, Start = `Return`, D-pad = arrow keys. Hold ≈30–50 ms; 150 ms double-steps the cursor.
- Path: boot → main menu → `PASS WORD` (Right then A) → type 8 characters (arrows move the 20/20/10 grid, A selects) → press **Start** to highlight `END` → press **A** to submit.
- Maximum-length entry works (all 8 slots fill; `END` remains reachable).
- Known codes tested on the real screen: `THQMPMD1` (Secret → Music Player), `THQHP100` (RAM flag set), `BwvzC35R` (novel, level 10), `BBBBBBBB` (rejected).
- Oracle method: mGBA CLI debugger (`mgba -d`), after one `frame` advance, write the 8 indices to `0x03005BC0`, set `cpsr=0x600000B2` (Thumb), `r14=0x0803DE90`, `r15=0x0803DB90`, `b/t 0x0803DE90`, `c`; read return `r0` and OUT[] at `0x03005BD8`.

## 5. Algorithm

Input: 8 chars, each mapped to index `IN[i] ∈ [0,49]` through `0x083E71FC`.

```python
S = IN[:]
for i in 0..3: S[i] ^= 1
p = ((IN[0] ^ 1) & 0x30) >> 4 + 1

A[0] = S[0]
for i in 1..7: A[i] = (S[i] - S[i-1] - p) mod 50   # mod with signed wrap +50

acc = (S[0] & 0x30)
for i in 2..7: acc += A[i]
acc += (A[0] & 0x30)
for i in (2,4,6): acc += A[i]                     # these three are added twice
count = 0
while int16(acc) > 49: acc -= 50; count += 1

accept  <=>  acc == A[1]  and  (count & 0x0F) == (A[0] & 0x0F)
```

On accept the payload is packed (all arithmetic 16-bit):

```
p0 = A[3] + 50*A[2];  p1 = A[5] + 50*A[4];  p2 = A[7] + 50*A[6]
OUT[0] = (p0 & 0x7F8) >> 3
OUT[1] = ((p0 & 7) << 5) | ((p1 & 0x7C0) >> 6)   # LEVEL
OUT[2] = ((p1 & 0xFC) << 2) | ((p2 & 0x600) >> 9)
```

`OUT[1]` is written as a byte to `0x03004964` and drives level selection. The two special codes are compared *before* this validator, so they do not satisfy its checks (verified).

Inverse (encoder): pick desired `A[2..7]`, search `A[0] ∈ [0,49]` until `(count & 15) == (A[0] & 15)`, set `A[1] = acc`, then invert the difference recurrence (`S[i] = (S[i-1]+p+A[i]) mod 50`, `IN[i] = S[i] ^ (i<4)`) and map `IN` back to characters.

## 6b. Enumeration

**Space definition.** 50 symbols × 8 positions = `50^8 = 39,062,500,000,000` possible strings. The two checks contribute ~6 bits (`acc == A[1]`, 1-in-50) and ~4 bits (`count&15 == A[0]&15`), so roughly `50^8 / 800 ≈ 4.9 × 10^10` strings are accepted. The payload is 8 u16 words; the level lives in the 9-bit `OUT[1]` field (`p0&7` supplies the top 3 bits, `p1&0x7C0` the low 6). `A[6]=1` / `A[7]=18` are constant across every published code and are therefore structural, not free fields (aliases exist — §16.4b).

**Validator model.** `validator.py` in `/tmp/opencode/oddworld` is a bit-exact reimplementation; it accepts 12/12 published level codes and rejects both `THQ…` codes plus garbage. `oracle_all.py` cross-checks the model against the ROM's own `0x0803DB90` for any input.

**Novel codes (absent from every published list).** Generated by `encoder.py`, confirmed by the ROM oracle (`OUT[1]`), and, for the first, typed on the real screen:

| Novel code | `OUT[1]` | In-game proof |
|---|---|---|
| **`BwvzC35R`** | 10 | Typed 8 chars on the on-screen keyboard; submitted with Start+A; gameplay starts, RAM `0x03004964 = 0x0A`, pause menu title `PAUSE: Journey` |
| `BcbfsPRq` | 9 | ROM oracle: accept, `OUT=[0,9,0,34,…]` |
| `Cvzx2JLk` | 1 | ROM oracle: accept, `OUT=[0,1,0,34,…]` |
| `FDHGfbd2` | 14 | ROM oracle: accept, `OUT=[0,14,0,34,…]` |
| `BwvzMsvH` | 16 | ROM oracle: accept, `OUT=[0,16,0,34,…]` |

Levels 9 and 10 are **not** reachable by any published code (those labels decode to 11 and 12), so `BwvzC35R` exercises a genuinely unadvertised combination.

**Bounds proven by rejection.** `BBBBBBBB` (8 valid-alphabet symbols, fails both checks) was entered on the real screen and produced the on-screen banner **"Incorrect Password!"**; the ROM oracle returns `r0=0` and leaves `OUT[]` unchanged. The two `THQ…` strings also fail the algorithmic validator (they are a separate hard-coded layer), confirming the two layers are distinct.

**Screen enumeration (all walked, RAM-observed where relevant).** Title/logo → main menu (NEW GAME, PASS WORD, Options, Gamespeak, Secret → Music Player after unlock) → PASS WORD entry screen (8 slots, 50-symbol 20/20/10 grid, END control; cursor col/row at `0x03000668/69`) → Options submenu (Controls, Configure, Game Credits, Back) → Gamespeak dialogue preview → pause menu (Options, Check Quarma, Restart Level, Password, Level Objectives, Quit Game, Resume) → gameplay HUD. The `Secret`→`Music Player` relabel and the "Incorrect Password!" banner were observed directly; the level index and flags were read from RAM as above.

## 7. Validation evidence

- **Observed** — emulator screenshots: main menu, password screen, Gamespeak preview, Options submenu, pause menu ("Journey"), gameplay, `THQMPMD1` → `Music Player`, "Incorrect Password!". RAM reads from uncompressed `gbAs` savestates: buffer `BwvzC35R`, level `0x03004964 = 0x0A`, health flag `0x030039FC = 0x01` after `THQHP100`, cursor coordinates.
- **Derived** — Thumb disassembly of `0x0803DB90`, `0x0803EB28`, `0x0803ED74`, `0x0803EE04`; literal-pool values decoded with `struct.unpack_from` (not objdump halfword order); reimplemented decoder agrees with all 12 published codes.
- **Oracle** — the ROM's own validator called from mGBA's CLI debugger (`IME` not needed; Thumb CPSR set, `r14=0x0803DE90`, breakpoint on return): accept/reject and `OUT[]` for published and synthesized inputs.
- **Inferred** — the semantic meaning of `OUT[0]`, `OUT[2]`, `OUT[3]` (likely progress/Quarma/character fields) was not exercised; only `OUT[1]` (level) was proven. The exact variable that makes the main-menu label change to "Music Player" was not isolated in RAM (the label change itself was observed).

## 8. Unknowns

- `OUT[0]`, `OUT[2]`, `OUT[3]` payload fields were decoded but not mapped to in-game effects; they vary with the published codes but their readers were not traced.
- The pause-menu `Password` display (the game's own generator) and the `Music Player` sub-screen were enumerated visually but not individually opened/captured; the guide's ~20-screenshot media budget was exhausted on the primary proofs.
- The music-player unlock's RAM flag was not isolated (the visual relabel is definitive, but no byte was diffed for it). `0x030039FC` is the infinite-health flag, not the music flag.
- Whether the game rejects very large decoded levels (≥64) was not tested in-game; the oracle accepts them, so any such rejection would be a later semantic range check, not part of `0x0803DB90`.
