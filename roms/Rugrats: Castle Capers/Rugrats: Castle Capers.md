## 2. Executive summary

The game has a **developer-intended 12-character password system** reached from
Main Menu → Password. It is not a lookup table: the ROM contains a full
charset validator, a nibble packer, a per-nibble key transform, and a 9-bit
parity/Hamming-style checker. The published level passwords are therefore only
a tiny sample of a very large valid space.

I recovered the complete validator, reimplemented it in Python, verified that
**all 6 correct published codes validate**, discovered that the widely
published level-6 code `FZLDVHMMDQRB` is **rejected by the real game**, and
generated **novel codes that the game accepts** (proven by on-screen keypad
entry with RAM-buffer verification). The input alphabet has aliases: 27
accepted characters collapse to 16 nibble values, so many spellings of each
code exist. The valid space is **2^39 = 549,755,813,888 packed codes**.

RAM evidence: the typed string is stored as 12 ASCII bytes at IWRAM
`0x03001E8E`; the cursor index is at `0x03001E7C`/`0x03001E80`; entry of the
12th character calls the validator at `0x080061B4`.

## 3. How to reproduce

### Emulator / environment
- mGBA 0.10.5 (SDL), `SDL_AUDIODRIVER=dummy`, Xvfb `:318`, 3× scale.
- Keymap verified: **A = `x`**, B = `z`, Start = `Return`, arrows = D-pad.
  (Start/`Return` does *not* activate menu items; `x` does.)
- Hold keys 50–100 ms with 100–200 ms gaps; shorter taps double-step or drop
  characters.

### Menu path (all reachable screens walked)
1. Boot; wait through the Nickelodeon splash and title ("Press START").
2. Press `Return` → Main Menu (Start Game / Options / Password).
3. **Options**: cursor Down once, `x` → Music Volume / Sound Effects Volume /
   Ambient Sounds (Off / Low / High); `z` returns. Walked with screenshots and
   savestate RAM diffs (the ambient setting byte changes in IWRAM).
4. **Start Game**: from Main Menu `x` → 16-page story sequence (text scripts
   64–74) → directly into Level 1 (Clock Work, Angelica). No hidden
   character-select entry on this path; the password buffer at `0x03001E8E`
   is untouched (`42 00 00…`) after this route.
5. Cursor navigation: Down twice, then `x` → **Password** screen.
4. The on-screen keyboard is a 21-letter grid `B C D F G H J K / L M N P Q R S T
   / V W X Y Z` plus a backspace cell. Cursor is a **linear index 0–20**:
   Right/Left = ±1 within a row (clamps at row ends), Down/Up = ±8.
   Move to column 0 first, then vertically, then horizontally to avoid
   row-edge clamping.
5. Press `x` to append the highlighted letter; press `z` (B) for backspace.
   The 12-slot buffer sits under the keypad. On the 12th character the game
   either starts the level (accept) or shows `INVALID PASSWORD`.

Non-password UI strings (`STAGE 1`, `STAGE 2`, `SECRET AREA`, `PAUSE`,
`WEEBLES`) are at file 0x1FB90–0x1FBB8; they are HUD labels, not cheat codes.
Text-script enumeration shows no other hidden/developer screen: 72 named
scripts occupy IDs 0 and 13–83 (main menu, options, password entry/error/
generator, character select, bonus, six level descriptions, credits, game
over, story and endings). IDs 1–12 have no ASCII string anywhere in the image,
in any case variant — they are control/placeholder scripts, not screens. No
`debug`, `level select`, `unlock` or `cheat` literal exists. The battery save
file is **0 bytes** — there is no battery-backed progress at all; passwords
are the only persistence mechanism.

## 5. Algorithm

Precise reimplementation (verified against every accepted published code):

```python
ALPHABET_AT = 0x083D77F8          # "BCFGJKLNPQRSTWXY*\0"
KEYS = [10, 5, 8, 5, 12, 14, 3, 2, 1, 7, 15, 4]

def char_to_nibble(c):
    # 0x08008588 = strchr(ALPHABET_AT, c); caller masks with 0xF.
    # Characters absent from the 17-byte string are found later in ROM,
    # producing the alias map in §6.
    return index_of_first_occurrence(c, starting_at=ALPHABET_AT) & 0xF

def validate(code):                       # 0x080083B8
    if len(code) != 12: return False       # driver enforces 12
    for c in code:
        if not (('A' <= c <= 'Z') or c == '*'): return False   # 0x080083F0
    nib = [char_to_nibble(c) for c in code]                    # 0x08008440
    # 0x080082D8: per-nibble ADD with key table
    t   = [(nib[i] + KEYS[i]) & 0xF for i in range(12)]
    bs  = bytes(t[i] | (t[i+1] << 4) for i in range(0, 12, 2)) # 6 bytes
    # 0x080080C4: nine parity checks
    return all( ((bs[cb] >> bit) & 1) ==
                (sum((bs[dat] >> b) & 1 for b in dbits) & 1)
                for cb, bit, dat, dbits in CHECKS )
```

Packing detail: nibble `i` is stored at bit `4*i` of the 48-bit little-endian
word (chars 0–7 in word 0, chars 8–11 in word 1). The transform adds
`KEYS[i]` modulo 16 to each nibble.

### Inverse / encoder (used to mint novel codes)

Pick 39 free bits; place them in all 32 bits of bytes 0–3, bits 0–5 of byte 4,
and bit 4 of byte 5. Compute the 9 check bits from the equations below, then
subtract the keys mod 16 and map each nibble back to a character.

## 6b. Enumeration

**Space definition.** 12 characters × 4 bits = 48-bit packed code. Nine
independent parity checks consume 9 bits, leaving **39 free bits**:
**2^39 = 549,755,813,888 distinct valid packed codes**. In character space the
27 accepted symbols and their aliases mean each packed value has on average
`(27/16)^12 ≈ 700` spellings, though the on-screen keypad can only express the
16 nibble values (21 keys with aliases).

**Validator model.** The Python decoder in `codec.py` agrees with the ROM on
every accepted published code and rejects the rejected ones. It was used as
the offline oracle to generate novel codes.

**Novel codes (absent from 3rd party cheat indexes):**

| Code | Payload | In-game proof |
|---|---|---|
| `LSPSJFWXYQCT` | all-zero transformed payload | typed on the real keypad, RAM buffer matched, game started Level 2 (Angelica) |
| `TWNGRGQBBPSC` | 0x712C168F26 | typed, RAM buffer matched; accepted (animation-frame difference only) |
| `NFJLBFBNJTQQ` | 0x75930CBC71 | typed, RAM buffer matched; accepted |
| `RRNRJNTXWYCJ` | 0x2E0F50FFF4 | typed, RAM buffer matched; accepted with the **orange-haired character** used by the "End" code — a combination no published list contains |

These exercise payload values no published list contains. In particular
`LSPSJFWXYQCT` is the all-zero-payload code: no hand-authored list would ever
contain it.

**Bounds proven by rejection.**
- `BBBBBBBBBBBB` — valid charset, parity fails → `INVALID PASSWORD` observed.
- `FZLDVHMMDQRB` — published "level 6" code; parity fails → `INVALID PASSWORD`
  observed; alias-exhaustion of all 2,343,750 spellings found **no** valid
  variant, so the published literal is unrecoverable as printed.
- `QGPCJNWXGWC*` — decoder accepts (`*` aliases `B`); not entered because the
  on-screen keypad has no `*` key. Statically derived alias, labelled
  **Derived**, not Observed.
- Transform direction resolved statically: the live path at `0x080082D8` uses
  `adds r1,r1,r2`; a near-identical unused duplicate at `0x080081F8` uses
  `subs`. Addition with the stored table reproduces all 6 correct published
  codes; subtraction fails them.

## 7. Validation evidence

- **Observed** — mGBA screenshots and savestate RAM dumps: main menu, options,
  password keypad, `INVALID PASSWORD`, eight accepted codes starting levels,
  RAM buffer at `0x03001E8E`, cursor bytes, per-keystroke savestate diffs.
- **Derived** — validator chain, alphabet string, key table, parity equations,
  charset check, encoder (all from objdump of the exact bytes at the addresses
  above), plus the Python decoder that reproduces every accepted code.
- **Inferred** — the game's "Your Password Is" generator screen exists (text
  scripts 19/20) but was not reached; the payload fields beyond the 9 parity
  bits were not assigned human-readable meanings (level/character are
  apparently derived from the hash-like payload, not a simple field).

No images are attached; screenshots and raw artifacts remain in
`/tmp/rugratscastle/`.

## 8. Unknowns

- The semantic mapping from the 39 free payload bits to level / character /
  collectibles was not fully characterized. Several accepted codes produce
  visually identical Level-2 spawns; `CSPLLQWPTWYJ` and the "End" code produce
  distinct characters. A full field decomposition would require reaching the
  in-game "Your Password Is" generator and varying progress state.
- The unused `subs` duplicate at `0x080081F8` is a red herring; the live path
  uses `adds`. This is now resolved, not an unknown.
- The `*` character is accepted by the validator but unreachable from the
  keypad; no in-game proof of an accepted `*`-containing code was obtained.
