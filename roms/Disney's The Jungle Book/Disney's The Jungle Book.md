Identity notes (Phase 0):

* Embedded-header scan: the 156-byte Nintendo logo occurs **once**, at file
  offset `0x4` (header `0x0`). This is a single-image ROM, not a multiboot
  pack or a 2-in-1.
* No appended data after the 8 MiB image; no trainer banner, no cracktro
  string in the first 4 KiB, `crt0` at `0x080000C0` is the stock
  `mov sp`/IRQ install sequence.
* The header was **rebuilt** at some point: `0xBE/0xBF` is `0x0000` and the
  complement byte is `0xC6` where the header bytes give `0xC2`. Per the
  guide (§16.1) these are normal artifact signals of a cleaned header, not
  of a gameplay patch; no code differences were observed.
* Credits (`0x00020F28`) identify **Visual Impact Production** (VIPROD) as
  developer and **Ubi Soft** as publisher, 2002–2003.
  This is **not** the 1994 Virgin/EastPoint side-scrolling platformer: the
  GBA SKU is an original overhead puzzle-adventure with experience points,
  six chapters, and a collectible gallery. Published Genesis/SNES/PC
  button codes (debug menu, level skip, "power-ups") belong to a different
  engine and do not apply (§16.11).

## 2. Executive summary

The game has a developer-intended **progress password system** behind
`Main Menu → Options → Code` (the "Code" icon is a padlock). It is the
cart's save mechanism: the game is listed as "Password Save", mGBA never
produced a non-empty battery save while playing (a 0-byte `.sav` was left),
and the only persistence screen in the front-end is this pad.

The `ENTER CODE` pad has **8 symbol slots**. Each slot cycles through a
**64-glyph alphabet** (index 0–63) made of case-sensitive consonants,
digits, card/pictogram glyphs and a `?` blank. The first **7 symbols carry a
42-bit LSB-first bitstream**; the **8th symbol is a checksum** equal to the
sum of the first seven symbol values `& 0x3F`.

The 42 bits decode into: a 3-bit field, a 1-bit flag, **13-bit experience
points**, a 5-bit field, a 4-bit fallback area index, a 5-bit field
(constrained to 0–16), a **4-bit area index (0–12)**, and **7 gallery-picture
flags**. The 4-bit area index selects the chapter/area directly — the code
screen is effectively a level select as well as a save code:

| area | start |
|---|---|
| 0 | no start (returns to menu) |
| 1 | Chapter 1 — The Jungle |
| 2, 3 | Chapter 2 — The Savannah |
| 4, 5 | Chapter 3 — The River |
| 6, 7 | Chapter 4 — The Temple |
| 8, 9 | Chapter 5 — The Swamp |
| 10, 11, 12 | Chapter 6 — Shere Khan's Lair |
| 13 | "escape": the 4-bit field at bit 22 is used as the area index |
| 14, 15 | rejected |

The validator additionally enforces a per-area XP range (e.g. area 1:
20–30 XP) and two cross-field rules. Any code that decodes outside those
ranges is answered with the on-screen message `Wrong code`.

No published code list exists for this SKU. Three codes generated by this
analysis were typed on the real pad and accepted: `BHBBBDBK` (Chapter 1,
RAM `xp=20 area=1`), `BHBBBDCM` (same progress plus gallery flag bit 1;
the gallery then shows the Kaa picture and RAM `[0x030005CB]=1`), and
`BpTBBhBF` (Chapter 6, RAM `xp=3700 area=12`). A one-symbol checksum
variant, `BHBBBDBM`, was typed and answered `Wrong code`.

## 3. How to reproduce

Emulator: mGBA 0.10.5 SDL, `-3` scale, under `Xvfb :339` + `openbox`,
`SDL_AUDIODRIVER=dummy`. Default SDL keymap: **A=`x`, B=`z`,
Start=`Return`, Select=`BackSpace`, D-pad = arrows**.

Always activate the window before keys: `xdotool windowactivate --sync <id>`
then a click inside the client; plain `windowfocus` alone intermittently
dropped XTEST key events in this environment.

Menu path (first boot shows a 6-flag language screen; pick English with A):

```
title "Press START"  -> Start
Main Menu            -> Left (Adventure->Options)   [order: Adventure,
                        Puzzle, Gallery, Options]
Options              -> Right Right (Code) -> A
ENTER CODE           -> 8 slots, all "?"
```

Pad controls (observed): **Up/Down** change the selected symbol (mod 64,
`?`+1 = `B`=0, all 64 values 0–63 are reachable, including the pictograms),
**Left/Right** move the slot cursor, **Start** submits, **B** leaves the
screen. The selected slot's glyph blinks, so a screenshot can catch it
blank — read the slot's value from RAM or take two frames. Entering the
screen prefills the pad with the code that encodes the *current* progress
(round-trip verified: after starting Chapter 1 with `BHBBBDBK`, re-entering
Code showed `BHBBBDBK`).

## 4. Address map

ROM addresses (`0x08000000 + file offset`); RAM addresses are GBA bus
addresses.

| Address | Kind | Meaning |
|---|---|---|
| `0x080101B8` | code | `bit_pack(value r0, count r1)`: append bits LSB-first to `0x030058E0`; cursors `0x030058D0` (byte) / `0x030058D4` (bit) |
| `0x08010218` | code | `bit_unpack(count r0) -> r0`: read bits LSB-first from `0x030058E0` |
| `0x08010288` | code | `encode_state()`: pack the progress struct into 7×6 bits (two layout branches selected by `hword[0x030005E0]`) |
| `0x08010408` | code | `decode(buf)`: unpack 42 bits into `0x03000550` fields |
| `0x08010578` | code | `validate(buf)`: `buf[7] == (sum(buf[0..6]) & 0x3F)` |
| `0x0801059C` | code | `checksum(buf)`: writes `buf[7] = sum(buf[0..6]) & 0x3F` |
| `0x080105C4` | code | `generate_and_copy()`: encode + checksum, copy 8 bytes to `0x030005EC` |
| `0x080105F0` | code | `apply(buf)`: validate → copy to `0x030058E0` → decode → range checks → returns 1 accept / 0 reject |
| `0x08010616`–`0x0801079E` | code | range-check layer; jump table at `0x0801067C` (13 entries, one per area index) |
| `0x08007BD4` | code | enter `ENTER CODE` screen: clears flags, calls `0x080105C4` to prefill the pad |
| `0x08007CE4` | code | per-frame pad handler: Up/Down auto-repeat timers, A/Start → `0x080105F0` |
| `0x08007DF8` | code | leave screen: calls `0x080105F0`, resets pad to eight `0x3F` on reject |
| `0x030005EC` | RAM | **code buffer**, 8 bytes: `[0..6]` symbol values, `[7]` checksum |
| `0x030058E0` | RAM | 8-byte work buffer used by bit pack/unpack |
| `0x03000550` | RAM | progress struct (see field table) |
| `0x0300057C` | RAM | XP, 32-bit (13 bits used) |
| `0x030005E6` | RAM | area index, 16-bit |
| `0x03000564` | RAM | 5-bit field destination (hword), enforced ≤ 16 |
| `0x030005B8` | RAM | 3-bit field destination |
| `0x0300058D` | RAM | 1-bit flag destination |
| `0x030005C9` | RAM | 5-bit free field destination |
| `0x030005B9` | RAM | 4-bit fallback area destination |
| `0x030005CA`–`0x030005D0` | RAM | 7 gallery flag bytes |
| `0x03000058` / `0x0300005C` | RAM | keys held / keys pressed (`~KEYINPUT & 0x3FF`) |
| `0x03000250`+2/+3 | RAM | Up/Down auto-repeat counters |
| `0x00020F28` | ROM | credits text (`JUNGLE BOOK !%%%%DEVELOPED BY%%VISUAL IMPACT…`) |
| `0x0051C000`–`0x00548C00` | ROM | multilingual dialogue text bank (ASCII, `%` = line break) |

## 5. Algorithm

### 5.1 Encoding

```
pack(fields):
  w = u1
    | f2   << 3
    | xp   << 4        # 13 bits
    | u3   << 17       # 5 bits
    | f5   << 22       # 4 bits
    | f6   << 26       # 5 bits
    | area << 31       # 4 bits
    | flags<< 35       # 7 bits
  for i in 0..6: sym[i] = (w >> (6*i)) & 0x3F
  sym[7] = (sym[0]+...+sym[6]) & 0x3F
```

The eight symbol values are rendered through the 64-glyph alphabet
(§6.1). Bits are LSB-first inside each 6-bit symbol.

### 5.2 Validation (0x08010578 + 0x080105F0)

```
accept(buf):
  if (sum(buf[0..6]) & 0x3F) != buf[7]: return 0        # checksum
  decode buf -> fields
  if f6 > 16:                        return 0
  if area <= 12:            idx = area
  elif area == 13:          idx = f5;  if idx > 12: return 0
  else:                     return 0                    # area 14/15
  if f2 == 1 and 1 <= idx <= 5:      return 0
  if xp not in XP_RANGE[idx]:        return 0
  return 1
```

On success `apply()` has already written the decoded fields into
`0x03000550`. The screen then reads the area: `area==0` returns to the main
menu, `area==13` re-uses `f5`, anything else starts that chapter's cutscene.

### 5.3 Observed screen behaviour

`A` does not submit (it is ignored or advances the cursor); **Start**
submits. A rejected code leaves the symbols on screen and prints
`Wrong code`. Entering the screen prefills the pad by running
`encode_state()` over the live progress, so the displayed code and the
accepted code are the same format in both directions.

### 6.1 The 64-symbol alphabet (value = pad index)

the rendering.

### 6.5 Gallery flags

Seven bits at word bits 35–41, decoded into seven separate RAM bytes
`0x030005CA…0x030005D0`. Observations:

* `flags=0x7F` (all seven bits) makes gallery pictures 1–3 real images
  (Bagheera, Mowgli with a wolf, Kaa).
* `flags=0x02` (bit 1, byte `0x030005CB=1`) makes picture 3 (Kaa) real
  while picture 2 is a locked "static" card, and picture 1 is still real.

The natural reading is **bit k → picture k+2** (pictures 2–8); bit 1 is
directly observed, bits 0 and 2–6 are inferred by the same pattern. The
gallery is reachable from the main menu without any code.

## 6b. Enumeration

### 6b.1 Space definition

* Input surface: 8 slots × 64 symbols = **64⁸ = 281,474,976,710,656**
  typed strings.
* Checksum constraint (1 symbol = 6 bits of redundancy): **2⁴² =
  4,398,046,511,104** checksum-valid strings.
* Semantic range layer (XP ranges, `f6≤16`, `f2`/area rule, area 14/15):
  **297,384,902,656** accepted strings (6.76 % of the checksum-valid
  space), i.e. **2.97 × 10¹¹**.
* Distinct progress points that the code can name (area, XP), ignoring the
  free fields and flags: **32,118** (8,192 of them in area 0, which does

### 6b.2 Novel codes (none of these appears in any published list)

There is no published GBA password list at all (see §7.2), so every code
below is unpublished. Each was **typed on the real pad** and confirmed by
screen and RAM.

1. `BHBBBDBK` — values `00 05 00 00 00 02 00 07`
   (area 1, XP 20, checksum 7).
   Typed → `CHAPTER 1: THE JUNGLE` cutscene, HUD `XP 20/230`.
   RAM after accept: `[0x0300057C]=20`, `[0x030005E6]=1`,
   `[0x030005CA..D0]=0`.
2. `BHBBBDCM` — values `00 05 00 00 00 02 01 08`
   (area 1, XP 20, gallery flag bit 1).
   Typed → Chapter 1; RAM `[0x030005CB]=1`; Gallery shows picture 1
   (Bagheera), a locked static card at 2, and picture 3 (Kaa) as a real
   image. This is the "unadvertised combination": a level/XP state that is
   reachable by the published-in-spirit Chapter 1 code, plus a gallery
   unlock that normal play only grants by finding statues.
3. `BpTBBhBF` — values `00 1D 0E 00 00 18 00 03`
   (area 12, XP 3700, no flags).
   Typed → `CHAPTER 6: SHERE KHAN'S LAIR`; RAM `[0x0300057C]=3700`,
   `[0x030005E6]=12`. This is the deepest area in the game (areas 10–12
   are all the last chapter) and is not a value the on-screen encoder
   produces during normal play until that point.

Bonus (injected, not typed): area 13 with `f5=2` reproduces
`CHAPTER 2: THE SAVANNAH`, proving the escape field; area 12 with the
maximum legal XP 5310 and gallery flag bit 1 is `s0cBBhC✳` (values
`20 2F 14 00 00 18 01 3C`).

### 6b.3 Bounds proven by rejection

All of these were fed to the game's own validator (`0x080105F0`) from the
code screen; the on-screen answer was `Wrong code` in every case:

| input | violation |
|---|---|
| `BHBBBDBM` (typed; last symbol M=8 instead of K=7) | checksum `sum=7 ≠ 8` |
| area 14 (values `00 32 00 00 00 1C 00 0E`) | `area>13` |
| area 15 | `area>13` |
| area 1, XP 19 | XP below 20 |
| area 1, XP 31 | XP above 30 |
| area 12, XP 3699 | XP below 3700 |
| area 12, XP 5311 | XP above 5310 |
| `f6=17` (area 1, XP 20) | `f6>16` |
| `f2=1` with area 3 | cross-field rule |

The exact boundary values were also confirmed in the accepting direction:
area 1 with XP 20 and XP 30 start Chapter 1; area 12 with XP 3700 and 5310
start Chapter 6; `f6=16` is accepted.

## 7. Validation evidence

### 7.1 Observed

* Pad with 8 slots, all `?`, reached from `Options → Code`.
* Every symbol 0–63 rendered by writing it into the pad and reading the
  glyph (10 batches of 7 symbols).
* Typed `BHBBBDBK` → Chapter 1 cutscene, HUD `XP 20/230`.
* Typed `BHBBBDCM` → Chapter 1; gallery picture 3 available.
* Typed `BpTBBhBF` → `CHAPTER 6: SHERE KHAN'S LAIR`.
* Typed `BHBBBDBM` → `Wrong code`.
* Re-entering the Code screen after Chapter 1 reproduced `BHBBBDBK`
  (encoder/decoder round trip, live).
* RAM reads after accept: `xp`, `area`, gallery flag byte (values above).

### 7.2 Derived

* Field order/widths from the bit packer at `0x080101B8` and the unpacker
  call list at `0x08010408`.
* Checksum from `0x08010578`/`0x0801059C` and the `apply` reject path.
* XP bounds from the 13-entry jump table at `0x0801067C`.
* `area==13` escape from `0x0801064E`–`0x0801065A`.
* The `f2`/area rule from `0x08010628`–`0x08010636`.
* Chapter banners per area from 13 generated codes (OCR of the banner).

### 7.3 Published-code check

* GameFAQs' GBA cheats page (`/gba/589586-.../cheats`) returns HTTP 403 to
  automated fetches and has no archived snapshot; its search snippet shows
  no GBA codes.
* Cheat Happens has empty cheat and trainer sections for this SKU.
* Every web hit for "Jungle Book cheats" is the 1994 Genesis/SNES/PC game
  (Virgin/EastPoint): debug menu from the briar patch, pause-menu
  `Up Up Down Down Left Right Left Right B A`, level skip, Game Genie.
  These are button codes for an engine with a pause-menu code handler; the
  GBA pause menu here has exactly `CONTINUE`/`QUIT` and no sequence
  handler, and the strings/patterns are absent from the image (below).
* Literal search for the obvious anchors: `PASSWORD`, `CHEAT`, `DEBUG`,
  `UNLOCK`, `CODE`, `LEVEL SELECT`, `OPTION` → **0 hits in ASCII,
  lowercase, the +0x20 shift, UTF-16LE and UTF-16BE**. The only menu
  artwork text (`ENTER CODE`, `Wrong code`, `PAUSE`, `Options`) is drawn
  from tiles, not stored as text — the ROM's dialogue bank is ASCII but
  these labels are not in it.
* `strings -n 4`: 118,535 ASCII strings; the keyword classes that do occur
  are story text (`secret` ×9, `level` ×5 — "you have finished the EASY
  level"), not code tables.

### 7.4 Button-code check

The pause menu has exactly two selectable entries (`CONTINUE`, `QUIT`) and
no sequence handler; pressing button strings on it does nothing. The
published Genesis/SNES sequences were also searched as raw key-mask
streams in both `held` and `active-low` encodings, forward and reversed,
as bytes and as `u16`:

* `Up Up Down Down Left Right Left Right B A` (power-ups): **0 hits**.
* the 20-press Genesis debug sequence prefix: **0 hits**.
* `A B B A A B B A`: one 8-byte run at `0x463D40`, inside a monotonically
  increasing byte table (graphics/index data), not a key-mask table.

## 8. Unknowns

* Meaning of the 3-bit field (`u1`), the 1-bit flag (`f2`), the 5-bit free
  field (`u3`) and the 5-bit `f6`. Their widths, RAM destinations and
  constraints are proven; their gameplay semantics are not. Candidates
  (difficulty, heart/energy counters, statue count) were not confirmed —
  the HUD only exposed XP during the tests.
* Complete bit→picture map for the gallery flags: bit 1 → picture 3 is
  observed; bits 2–6 are inferred to follow the same sequence.
* The two encoder layouts selected by `hword[0x030005E0]` (the "no-save"
  branch writes a constant 13 in the area slot) are only exercised through
  the prefill path; their semantic difference is not fully mapped.
* No published list existed to compare against, so "novel" here means
  "absent from every list found", not "differs from a known list".

## 9. Tooling

* `codec.py` — alphabet, field pack/unpack, checksum, validator model and
  code generator (`python3 codec.py new <area> <xp> [flags]`,
  `python3 codec.py <CODE>` to decode/validate).
* `pstate.py` — patch bytes in an mGBA `.ss` savestate (PNG `gbAs` chunk,
  re-deflated with a correct CRC) and write a loadable state; used to feed
  candidate buffers to the game's validator when typing 60+ symbols was
  impractical. IWRAM maps to state offset `0x19000 + (addr - 0x03000000)`;
  `0x030005EC` is therefore state `0x195EC`.
* `kk.py` — `xdotool` key driver: `windowactivate --sync`, click inside the
  client, hold 50–120 ms, release; captures `import -window root` and
  crops `720x480+282+312`.
* mGBA 0.10.5, Xvfb 21.1.16, openbox, tesseract 5.5 (banner OCR),
  `arm-none-eabi-objdump -M force-thumb`, Capstone.
* Key screenshots (work dir `/tmp/opencode/junglebook`): `m6.png` (pad),
  `cs0.png` (all `?`), `typedc.png` (`BHBBBDBK`), `typed_okc.png`
